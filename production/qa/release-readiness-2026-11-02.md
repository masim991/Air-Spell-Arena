# 출시 준비 점검 — 2026-11-02

Claude Code에서 스튜디오 단계·코드·출시 점검을 요청했고 보안 담당 결과를 받았다. 다른 스튜디오 에이전트 3개는 셸 권한 문제로 실패했으며, 엔진 전문 검증은 Python/Pygame 미지원으로 수행하지 못했다. 별도 검토 결과와 실제 테스트로 아래 항목을 교차 확인했다.

최종 소스에서 pytest 184개와 Ruff가 통과했다. Windows 실행 파일을 재빌드해 카메라가 꺼진 메뉴의 시작을 확인했다. 실제 웹캠 시험은 수행하지 않았다.

## 코드와 동작

- 일일 챌린지 최고 기록이 일반 난이도 기록을 덮어쓰는 문제를 분리했다.
- 일시정지 화면이 실제 음량을 읽고 일시정지 시간을 경기 점수 계산에서 제외한다.
- 카메라 없는 상태의 숫자 키 주문, 일일 기록 분리, 일시정지 전환에 회귀 검사를 추가했다.
- 신규 설치에서는 웹캠 디버그 창을 기본으로 숨기고 잘못 저장된 카메라 번호는 기본값으로 복구한다. 기존 사용자가 저장한 디버그 창 설정은 유지한다.
- Python 지원 범위를 확인된 3.12로 맞추고 키보드 시작 방법을 현재 메뉴에 맞게 고쳤다.
- `game.py`의 프레임 처리와 `fp_renderer.py`의 보스 렌더링은 길고 결합도가 높다. 큰 구조 변경은 별도 작업에서 화면·전투 회귀 기준을 마련한 후 진행한다.

## 디자인과 접근성

- 카메라를 끈 정상 상태를 위험 색상으로 표시하지 않는다.
- 접근성 우선 개선 후보: 조작 전체의 키보드 접근, 키 재지정, 글자 크기·대비, 색 외의 공격 구분, 화면 흔들림 조절. 현재 적용 여부와 실사용 검증을 각각 확인해야 한다.
- 저폴리 폐허와 HUD의 완성도는 플레이어 평가가 필요하며, 단일 스크린샷만으로 최신 시각 경향이나 상용 수준을 판정할 수 없다.
- 참고: [Microsoft 입력 접근성](https://learn.microsoft.com/en-us/xbox/accessibility/xbox-accessibility-guidelines/107), [Steam 접근성 기능 표시](https://partner.steamgames.com/doc/accessibility_features).

## 배포 전 남은 확인

- 실제 웹캠 제스처, 카메라 권한 거부·분리 후 복구, 다양한 기기와 5~10분 이상 장시간 플레이를 실측한다.
- 카메라가 첫 실행 고지보다 먼저 켜지는 흐름과 MediaPipe 초기화 실패 시 카메라 자원 정리를 검토한다.
- 키보드 전용 플레이의 모든 메뉴·설정 조작을 실제 실행 파일에서 확인한다. 자동 화면 키 입력으로는 주문 발사를 확인하지 못했다. 숫자 키 이벤트 단위 검사는 전체 접근성 검증을 대체하지 않는다.
- 추적 중인 음원과 이미지·폰트·의존성의 배포 권리를 확인한다. 기본 빌드는 음원 권리 확인 전까지 무음이다. 이미 Git에 들어간 파일은 무음 빌드와 별도로 점검한다.
- 깨끗한 Windows 환경에서 실행·저장·재실행·종료, 배포 파일 서명 및 백신 오탐 여부를 확인한다.
- 배포 플랫폼이 정해지면 해당 플랫폼의 표시 문구와 심사 요구를 확인한다. Steam을 택할 경우 [스토어 및 빌드 검토 절차](https://partner.steamgames.com/doc/store/review_process)를 따른다.
- GitHub Actions는 `feat/**` 브랜치 push에도 실행되도록 설정했으나 원격 실행은 push 후에만 확인할 수 있다.

**판정: 출시 직전 검토 중. 실제 하드웨어·권리 확인 전에는 출시 승인으로 간주하지 않는다.**
